**Explanation of the code:**

The `src/data/seed.ts` file is the **seed data source** for the entire e-commerce application. It contains a static array of 12 `Product` objects that serve as the initial product catalog when no real backend database is available.

**Key design decisions:**

1. **Type safety** — Every entry is typed as `Product` (imported from `src/types`), so TypeScript will enforce that every field matches the interface exactly. This prevents bugs at compile time.

2. **Product diversity** — The 12 products span 6 distinct categories (`Electronics`, `Clothing`, `Home & Kitchen`, `Sports`, `Books`, `Fashion`) and multiple subcategories, ensuring the category filter, search, and tag filters all have meaningful data to work with.

3. **Realistic pricing** — Each product has a `price` and optionally an `originalPrice` to simulate a discount. The `ProductCard` component uses this to show a strikethrough original price and a percentage badge.

4. **`tags` array** — Each product carries a subset of `["best", "new", "sale"]` tags. The `TagFilter` component uses these to let users filter by tag, and the `ProductCard` renders a colored badge for each.

5. **`featured` flag** — Products marked `featured: true` are used by the `FeaturedProducts` component to populate the "Bestsellers" section on the home page.

6. **`stock` field** — Used by the cart and checkout flow to validate that the user can't add more than the available quantity.

7. **`createdAt`** — A real ISO date string used by the `sort` function in `useProducts` to support "Newest first" sorting.

8. **`rating`, `reviewsCount`, `brand`, `sku`, `subcategory`** — These fields are all used by the `ProductDetail` page to display a complete, realistic product page.

1. **Type safety** — Every entry is typed as `Product` (imported from `src/types`), so TypeScript will enforce that every field matches the interface exactly. This prevents bugs at compile time.

2. **Product diversity** — The 12 products span 6 distinct categories (`Electronics`, `Clothing`, `Home & Kitchen`, `Sports`, `Books`, `Fashion`) and multiple subcategories, ensuring the category filter, search, and tag filters all have meaningful data to work with.

3. **Realistic pricing** — Each product has a `price` and optionally an `originalPrice` to simulate a discount. The `ProductCard` component uses this to show a strikethrough original price and a percentage badge.

4. **`tags` array** — Each product carries a subset of `["best", "new", "sale"]` tags. The `TagFilter` component uses these to let users filter by tag, and the `ProductCard` renders a colored badge for each.

5. **`featured` flag** — Products marked `featured: true` are used by the `FeaturedProducts` component to populate the "Bestsellers" section on the home page.

6. **`stock` field** — Used by the cart and checkout flow to validate that the user can't add more than the available quantity.

7. **`createdAt`** — A real ISO date string used by the `sort` function in `useProducts` to support "Newest first" sorting.

8. **`rating`, `reviewsCount`, `brand`, `sku`, `subcategory`** — These fields are all used by the `ProductDetail` page to display a complete, realistic product page.
